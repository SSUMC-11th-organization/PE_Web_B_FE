# 실제 서버 검증·미션 기록 안내

## 1. 앱 실행

```powershell
cd C:\dev\UMC\PE_Web_B\mins\Week8\Week8_Mission\umcine
pnpm dev --host 127.0.0.1 --port 5189
```

브라우저에서 `http://127.0.0.1:5189`를 연다. 5188은 로컬 가상 서버 검증용이므로 제출용 실제 API 확인은 5189에서 한다. 이미 실행 중이면 터미널 주소를 따른다.

## 2. 본인 계정 만들기와 로그인

1. `/signup`에서 사용할 이메일과 아직 쓰이지 않은 닉네임(2~12자), 영문 대소문자·숫자·특수문자가 포함된 8자 이상 비밀번호를 입력한다. 평소 비밀번호를 재사용하지 않는다.
2. 이메일·닉네임 중복 확인을 각각 완료하고 비밀번호 확인까지 입력한다. 값을 바꾸면 중복 확인을 다시 한다.
3. 가입 성공 후 `/login`에서 방금 가입한 이메일·비밀번호로 로그인한다. 기존 공식 실습 서버 계정이 있으면 가입을 생략해도 된다.
4. 홈으로 이동하고 헤더에 본인 닉네임이 표시되는지 확인한다. 새로고침해도 로그인 상태가 유지되어야 한다. 로그인한 상태에서 `/login`을 직접 열면 홈으로 이동해야 한다.

임의 이메일·비밀번호로 로그인되던 7주차 화면과 다르다. 이제 서버에 가입된 계정의 비밀번호가 맞아야 로그인된다. 로컬 가상 계정은 공식 서버에 등록하지 않았으므로 사용할 수 없다. 비밀번호·토큰을 채팅으로 보내지 않는다.

## 3. 필수 동작 확인

1. 내 정보 → 정보 수정에서 새 닉네임을 저장한다. 헤더와 내 정보에 함께 반영되는지 본다. 개발자 도구 Network에서 PATCH /v8/members/me 뒤 추가 GET /v8/members/me 없이 갱신되는지 확인한다. Network 목록은 저장 직전에 지우고, 검사 중 페이지 새로고침은 하지 않는다.
2. 영화 상세에서 즐겨찾기를 추가한다. 내 정보 목록에 해당 영화가 나타나고, 다시 상세로 들어가도 추가된 상태인지 확인한다. 삭제하면 목록에서 사라져야 한다.
3. 영화 상세에서 별점 4점과 짧은 후기를 저장한다. 5점·다른 후기로 수정하고 새로고침하여 저장을 확인한다. 평점 삭제 → 확인을 누르면 새 평점을 입력하는 상태로 돌아오는지 본다.
4. 로그아웃 후 `/profile`과 `/profile/edit`에 직접 들어가면 로그인으로 이동하는지 확인한다. 잘못된 비밀번호 로그인 실패 후 다시 입력할 수 있는지도 확인한다.
5. 오류가 나면 오류 문구와 해당 요청의 URL·상태 코드만 알려준다. Authorization 헤더, 토큰, 로그인 요청 본문은 공유하지 않는다.

프로필 이미지·이메일 변경과 탈퇴는 이 서버의 이번 필수 API에 없다. 이미지 업로드는 이번 확인 항목에서 제외한다.

## 4. 캡처 또는 짧은 영상

다음 4묶음이면 구현 결과를 보여 주기 좋다. 긴 과정 전체보다 결과가 드러나게 남긴다.

- 로그인 성공 후 홈/헤더: 본인 닉네임 표시. 로그인 폼만 찍으면 실제 로그인 성공 증거가 부족하다.
- 닉네임 수정: 수정 결과 화면 + Network의 PATCH 요청 목록. 토큰이나 비밀번호가 보이는 Headers/Payload 탭은 닫는다.
- 즐겨찾기: 상세 추가 상태와 내 정보의 실제 목록. 추가 → 목록 → 삭제는 짧은 영상도 가능하다.
- 평점: 4점 등록 → 5점 수정 → 삭제 후 빈 폼. 영상 하나 또는 결과 캡처 여러 장으로 남긴다.

로그아웃 후 보호 경로가 로그인으로 이동하는 결과도 한 장 추가하면 좋다. 실제 서버 동작을 확인한 후 그 결과만 기록한다.

## 5. Notion 필수 미션 토글

아래는 확인 후 본인 말로 고쳐 사용할 문장이다.

> useMutation으로 회원가입과 로그인 요청 상태를 관리했다. 로그인 토큰을 저장하고 인증 API에 전달했으며, 로그인 후 내 정보 조회 결과를 표시했다. Route Group과 공통 Layout Route로 로그인 전용 화면을 묶었다. 닉네임 수정 응답을 setQueryData로 반영해 추가 조회 없이 헤더와 내 정보를 갱신했다. 즐겨찾기 목록·상태 조회와 등록·삭제, 평점 조회·등록·수정·삭제 결과가 화면에 반영되는 것을 확인했다.

그 아래에 캡처/영상을 붙이고 핵심 코드 링크 4묶음을 첨부한다.

1. `src/routes/(authenticated)/_authenticated/route.tsx`와 `src/components/layout/authenticated-layout.tsx`: 로그인 전용 폴더·Outlet·인증 확인.
2. `src/hooks/use-login-mutation.ts`, `src/api/auth-api.ts`: 로그인·토큰·인증 요청.
3. `src/hooks/use-update-me-mutation.ts`: 응답으로 회원 캐시 직접 갱신.
4. `src/hooks/use-favorite-mutation.ts`, `src/hooks/use-rating-mutation.ts`: 즐겨찾기·평점 변경과 캐시 반영.

GitHub에 푸시한 뒤 해당 파일에서 핵심 줄 번호를 클릭하고 Shift로 끝 줄을 선택한 다음 `… → Copy permalink`로 고정 링크를 복사한다. Notion에는 링크와 한 줄 설명을 붙이면 된다. 코드를 통째로 복사할 필요 없다. 현재 작업 브랜치는 `mins/#75`, 이슈는 #75이며 PR 작성 전 실제 서버 검증 결과를 함께 정리한다.

핵심 키워드·학습 후기·스터디 사진은 별도 항목에 본인이 작성하고, 미션 기록이 포함된 Notion 공유 링크를 제출한다.
